## Design Read & Written Purpose Ledger (`R-31`, Block 3)

> Reading this as: Multi-platform disaster clarity and rumor verification workspace for Indonesian crisis coordinators, field responders, and public wire readers, in a Crisis Newsroom & Emergency Dispatch Wire style, dial **ENERGY 2 / RHYTHM 2 / MOTION 1**.

| Decision Area | Purpose-Gate Justification (1-Line Reason) |
| :--- | :--- |
| **Palette (`R-01`, `R-29`)** | Uses warm newsprint `#F8F7F4` / command charcoal `#111315`, crisp white `#FFFFFF` / slate `#1A1D21` surfaces, and 1 core vermilion accent `#C83219` reserved for primary dispatch actions so daylight/blackout legibility never fights gradient haze or rainbow badge noise. |
| **Theme Toggle (`R-21`, `R-34`)** | Ships an explicit Light/Dark toggle across Web (`web/src/App.tsx`), Android (`MainActivity.kt`), and Apple (`SigapWireAppleApp.swift`) because disaster responders shift between sunlit impact zones and night-shift desks. |
| **Typography (`R-06`)** | Pairs `Source Serif 4` display headlines (editorial wire seriousness), `Plus Jakarta Sans` UI/body copy (high legibility across Indonesian/English text), and `IBM Plex Mono` strictly for real operational telemetry (`ON_DEVICE` / `IN_CLOUD`, latency `ms`, token budgets, `[PHONE_1]` redaction tags). |
| **Borders & Radii (`R-11`, `R-12`)** | Restrains surfaces to hairline `1px` borders with `8px` panels, `6px` buttons/inputs, and `4px` status tags; shadow (`0 1px 2px rgba(0,0,0,0.06)`) appears only on the sticky top bar (`TopNav.tsx`) so hierarchy relies on typography and border weight rather than floating cards. |
| **Motion (`R-19`)** | Restricts motion to subtle color transitions, native determinate token/download progress bars, and live streaming text arrival (`prefers-reduced-motion: reduce` honored in `web/src/index.css`). |
| **Icons & Wordmark (`R-04`, `R-22`, `R-23`)** | Uses a plain typographic serif wordmark with a `10px` square vermilion dispatch mark and zero decorative AI icons (`Sparkle`, `Robot`, `Lightning`, illustrations, or capsule promo badges). |
| **Rhythm & Layout (`R-05`, `R-14`, `C-3`)** | Each view matches its operational workflow (two-column intake/diff workspace in `CommandDesk.tsx`, queue + 4-tab studio in `BroadcastStudio.tsx`, single-column dispatch wire in `PublicCrisisWire.tsx`) with asymmetric column ratios (`5:7` on desktop) instead of copy-paste Bento cards. |

## Numbered Findings List (Mode 2 Audit)

1. **[R-03] [HIGH / Hard Gate] Secondary interactive controls and grounding source links are under the 44px minimum tap target height.**
   - *Where:* [CommandDesk.tsx](../web/src/components/CommandDesk.tsx#L530) ("Remove Image" `min-h-[36px]`, grounding links `min-h-[36px]`), [BroadcastStudio.tsx](../web/src/components/BroadcastStudio.tsx#L396) (audience tabs `min-h-[40px]`, Copy buttons `min-h-[36px]`), [PublicCrisisWire.tsx](../web/src/components/PublicCrisisWire.tsx#L230) (channel tabs `min-h-[40px]`, source links `min-h-[36px]`, adaptation buttons `min-h-[40px]`), [LiveAlertsScreen.kt](../android/app/src/main/kotlin/dev/sigapwire/android/ui/LiveAlertsScreen.kt#L306) (channel buttons `38.dp`, Copy button `42.dp`, source buttons `38.dp`), and [MainActivity.kt](../android/app/src/main/kotlin/dev/sigapwire/android/MainActivity.kt#L100) (theme button `40.dp`).
   - *Reason:* Raising those secondary interactive controls from `36px`/`40px` (`38.dp`/`42.dp`) to `44px` (`44.dp`) brings every clickable target up to the `R-03` mobile tap floor.

2. **[R-35] [HIGH / Hard Gate] Apple SwiftUI companion build and interactive click-through remain unverified on Windows.**
   - *Where:* [SigapWireAppleApp.swift](../apple/SigapWireApple/SigapWireAppleApp.swift), [BriefingWireView.swift](../apple/SigapWireApple/Views/BriefingWireView.swift), [QuickTextIntakeView.swift](../apple/SigapWireApple/Views/QuickTextIntakeView.swift).
   - *Reason:* Authored against verified Firebase AI Logic v12.13.0+ documentation on Windows, where `xcodebuild`, iOS Simulator, and Apple Intelligence cannot run; must be generated (`xcodegen generate`), compiled, and clicked through on macOS (`MacBook Air M5`) before claiming Apple runtime verification.

3. **[R-35] [HIGH / Hard Gate] Automated post-edit DOM click-through matrix (dark mode + 360px + 200% zoom) is missing from recorded test artifacts.**
   - *Where:* [web/](../web/src/App.tsx).
   - *Reason:* Production TypeScript/Vite build and live user functional smoke checks passed, but adding a recorded Playwright or DevTools click-through covering both light/dark themes and 360px / 200% zoom would turn manual sign-off into repeatable `R-35` evidence.

4. **[R-06] [MEDIUM / Purpose-Gate] Minor uppercase wide-tracked subheaders lack explicit taxonomy differentiation from telemetry tags.**
   - *Where:* [CommandDesk.tsx](../web/src/components/CommandDesk.tsx#L358) (`uppercase tracking-wide` on `"Load Synthetic Drill Sample"`) and [BroadcastStudio.tsx](../web/src/components/BroadcastStudio.tsx#L187) (`uppercase tracking-wide` on `"Synced Incident Queue"`).
   - *Reason:* Using sentence-case sans labels for section subheaders reserves uppercase tracking exclusively for monospaced operational telemetry (`ON_DEVICE`, `IN_CLOUD`, `SYNTHETIC DRILL`).

5. **[R-39] [LOW / Quality Lock] Selectable intake queue items in Broadcast Studio rely on border-color shift without a checked background tint or hover feedback.**
   - *Where:* [BroadcastStudio.tsx](../web/src/components/BroadcastStudio.tsx#L234-L282).
   - *Reason:* Adding a subtle background tint (`var(--bg-subtle)`) on hover and checked state strengthens selection affordance alongside the checkbox and vermilion border without relying on color alone.

6. **[R-35 / R-03] [LOW / Hard Gate follow-up] Apple QuickTextIntakeView scenario preset buttons and token chips sit at compact padding without explicit `.frame(minHeight: 44)` on preset chips.**
   - *Where:* [QuickTextIntakeView.swift](../apple/SigapWireApple/Views/QuickTextIntakeView.swift).
   - *Reason:* While primary CTA buttons use `minHeight: 44`, horizontal drill preset buttons use compact vertical padding (`6pt`), which would benefit from `minHeight: 44` for iPhone touch ergonomics.
